# Private live Watch voice prototype

**Build 4 supersedes the phone-signaled path described below.** The Watch now authenticates, discovers Dot and owns signaling/audio directly, using an encrypted setup reply and device-only Keychain. Phone heartbeats are removed from its active voice path. Physical locked-phone, absent-phone and ten-minute tests remain open. [Current standalone design](WATCH-STANDALONE.md).

The following describes build 3 and its recorded physical evidence. A subsequent build 3 trial failed with `phone_lease_lost`; the user reports the phone is typically locked.

The Private Watch app exposes **Talk to Dot**, **Mute/Unmute** and **End**. It uses the authentic cached character; launch/complication/Refresh never starts recording. Local **Test Watch audio** and live voice cannot run together. Public configurations exclude both private audio interfaces and microphone declaration.

The Watch prepares native audio and a WebRTC offer. Its paired iPhone checks account/Dot hashes and installation/revision, resolves its own cached sign-in, releases any prior app-owned session, creates/attaches the same Dot voice connection, and returns an ephemeral answer. The Watch handles authenticated ICE, DTLS fingerprint verification, SRTP/Opus and voice events directly. The iPhone explicitly activates Watch audio after transport readiness. WatchConnectivity carries bounded session control/SDP; it carries neither microphone packets nor account credentials.

Audio callbacks use nonisolated Sendable factories and bounded buffers. Capture retains at most 120 ms, and delayed cycles can encode up to three fresh 20 ms frames. The clock maintains an absolute cadence. Capture overflow drops only excess oldest samples. Received packets have a bounded reorder wait measured in elapsed time, with a 120 ms startup target and playback cushion; scheduled playback is capped at 240 ms. Completion callbacks update their thread-safe frame count immediately instead of waiting for UI scheduling. UI amplitude updates run at 10 Hz. Mute discards captured/primed samples and sends generated silence for server turn detection. Speech-start events clear queued playback. End closes capture, playback, network and buffers; the phone waits for a positive Watch audio-stop acknowledgement before another device can allocate. Three-second control heartbeats enforce leases on both devices. A failed release retains End for retry.

Temporary session setup is not persisted. `Documents/voice-diagnostics.json` stores fixed phase/error labels, timestamp, build, audio/RTP/event counts, dropped-frame/packet counts, late ticks and release flags only. It stores no IDs, SDP, credentials or transcripts. Empty playback refills also include normal pauses between responses; that counter alone does not prove an underrun. Character revocation ends an active Watch attempt. Approval/tool payloads are never executed by this client.

The user completed dialogue on the physical Watch with build 2, but reported substantial jitter in Dot's spoken responses. Signed build 3 is installed on the test iPhone and Watch; timing, reordering and playback accounting changes pass twenty audio regression tests. The user reports clearer replies with little or no jitter on build 3. Its safe report shows no receive gaps, late packets, inbox/queue overflow or session failure, and confirms clean audio release. The phone reports ready with cached sign-in and the authentic character. This is a short physical comparison; ten-minute/background acceptance remains open. The uplink framer still discarded 57,024 frames in this trial, so input timing/quality needs review before full acceptance. [Initial exchange/build evidence](fixtures/watch-live-voice-validation.json), [jitter fix and physical comparison](fixtures/watch-jitter-fix-validation.json).

The direct adapter still selects one public IPv4 UDP candidate. TURN, IPv6, candidate failover and safe resumption are not implemented. Apple restricts low-level Watch networking outside allowed audio/call experiences, and simulators do not enforce the same restriction. Background mode and successful compilation are insufficient evidence. Initial physical voice connected; acceptable quality and a ten-minute locked-phone/wrist-down test remain required before direct transport is selected as production-ready. [Apple TN3135](https://developer.apple.com/documentation/technotes/tn3135-low-level-networking-on-watchos), [background audio guidance](https://developer.apple.com/documentation/watchkit/playing-background-audio).

The Watch transport uses a byte-identical snapshot of upstream `1amageek/swift-webrtc` revision `f35ac95e4e743b1fb6be50c184e7d3691ef7ddb1`, with a local manifest naming its module/product `WatchWebRTC`. This avoids Xcode product/module collisions with the pinned iPhone binary SDK. The source hashes, original manifest/README and resolved transport pins are retained. Run `python3 tools/verify_watch_source.py` before rebuilding; change source only through an explicit reviewed dependency update. Exact source notices are packaged. Upstream swift-networking has no separate license file in this pinned source; redistribution review remains open.

After installing the matching personal apps, keep the iPhone nearby, configured and idle. On Watch tap **Talk to Dot**, allow microphone access, speak and confirm a response; then Mute and End. If it fails, preserve the exact message and read the safe voice report before another install. Never infer physical voice from the local synthetic codec check or the CarPlay fixture tests.
